## 1. Классификация данных и необходимость защиты

### 1.1 Классы данных по типу и чувствительности

| Класс данных             | Примеры                                                                 | Состояние          | Необходимость защиты                                                |
|--------------------------|-------------------------------------------------------------------------|--------------------|----------------------------------------------------------------------|
| Персональные (PII)       | ФИО, дата рождения, телефон, email, паспорт, адрес, место работы/учёбы | At rest, In transit| Требование 152‑ФЗ, риск идентификации и злоупотребления данными     |
| Медицинские (PHI)        | Диагнозы, анализы, назначения, медкарты, хронические заболевания       | At rest, In transit| Специальная категория ПДн, критические репутационные и правовые риски |
| Финансовые (FIN)         | Счета, договоры, суммы оплат, реквизиты, чеки ККМ                      | At rest, In transit| Риски мошенничества, финансовых потерь, ответственность перед ФНС   |
| Тех. идентификаторы (TECH_ID) | Логины, внутренние ID пациентов, IP‑адреса, ID касс/устройств   | At rest, In transit| По совокупности могут деанонимизировать пользователя, использоваться в атаках |
| Операционные служебные   | Логи, метрики, конфигурации, временные файлы                           | At rest, In transit| Могут содержать PII/PHI/FIN, нужны маскирование и ограниченный срок хранения |

### 1.2 Классификация по состоянию

**At rest:**

- Файловый сервер (Excel‑журналы, JPG/PDF, сканы медкарт и договоров).
- Базы 1С и будущие БД CRM/порталов/EMR/биллинга.
- Логи приложений, бэкапы и архивы.
- Озеро данных / аналитическое хранилище.

**In transit:**

- Внутренние каналы: доступ к файловому серверу, межсервисные вызовы (CRM, EMR, биллинг, 1С).
- Внешние каналы: портал пациента, интеграция лаборатории по API, пересылка отчётов/файлов наружу.

## 2. Базовые инструменты защиты (at rest / in transit)

### 2.1 Защита at rest

| Класс данных | В чём необходимость защиты                                  | Инструменты защиты                                                                                       |
|--------------|-------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------|
| PII          | Утечка ведёт к идентификации пациентов, нарушениям 152‑ФЗ   | Шифрование дисков (BitLocker/LUKS), шифрование колонок/таблиц в БД (AES‑256), строгие ACL на файловом сервере |
| PHI          | Особо чувствительные медданные                              | Шифрование БД EMR, отдельные схемы, FDE на серверах, защищённые хранилища для сканов, контроль бэкапов   |
| FIN          | Риск мошенничества, ответственность перед ФНС               | Шифрование БД биллинга и 1С, зашифрованные папки для договоров/счётов, разграничение доступа по ролям     |
| TECH_ID      | Возможность деанонимизации, подготовки атак                 | Шифрование лог‑хранилищ, ограниченный доступ к логам, сокращённые сроки хранения                         |
| Логи/архивы  | Часто содержат PII/PHI/FIN и «забываются»                   | Шифрование лог‑хранилища, маскирование чувствительных полей, агрессивные TTL для логов и временных файлов |

### 2.2 Защита in transit

| Сценарий                                   | В чём необходимость защиты                   | Инструменты защиты                                    |
|--------------------------------------------|----------------------------------------------|-------------------------------------------------------|
| Портал пациента ↔ backend                  | Передаются PII/PHI/FIN                       | HTTPS/TLS 1.2+, HSTS, современные ciphersuites        |
| Портал ресепшена/врача ↔ backend           | Вся работа с PII/PHI                         | Внутренний TLS, при необходимости mTLS                |
| CRM/EMR/биллинг ↔ другие сервисы           | Обмен PII/PHI/FIN                            | mTLS между сервисами, TLS‑терминация на ingress       |
| Интеграция с лабораторией по API           | Передача PHI наружу                          | TLS + VPN/IPsec, жёсткие API‑контракты (минимизация данных) |
| Почта, внешние выгрузки                    | Файлы с PII/PHI/FIN                          | TLS для SMTP, шифрование вложений/архивов, DLP‑проверка |
| Доступ к БД/файлам из филиалов / удалённо  | Передача PII/PHI/FIN/TECH_ID по сети         | VPN, TLS‑подключения к БД, запрет «голого» SMB/SQL    |

## 3. Инструменты защиты, которые нужно добавить

### 3.1 Для шифрования at rest

- Полное шифрование дисков серверов (FDE) для:
    - файлового сервера (документы, Excel, сканы);
    - БД 1С и новых бизнес‑систем;
    - хранилища бэкапов.
- Шифрование на уровне БД:
    - колонки с PII/PHI/FIN;
    - отдельные схемы/таблицы с медданными и финансовыми данными.
- Разделение хранилищ:
    - `SecureDocs` — зашифрованное хранилище документов с PII/PHI/FIN;
    - отдельные папки/БД для документов без ПДн.

### 3.2 Для шифрования in transit

- Обязательное использование TLS 1.2+:
    - для всех веб‑порталов (пациент, ресепшен, сотрудники);
    - для API между сервисами (mTLS, если есть сервис‑mesh/ingress).
- VPN/IPsec:
    - интеграция с лабораторией, банком, внешними партнёрами;
    - защищённый доступ филиалов/удалённых сотрудников.
- Запрет незашифрованных протоколов:
    - SMB/SQL без TLS;
    - старые версии протоколов (SSL, устаревшие шифры).

## 4. Автоматизированный контроль

### 4.1 Контроль за данными и конфигурацией

- **Data Discovery & Classification**
    - Регулярное сканирование БД и файловых хранилищ на наличие PII/PHI/FIN (по шаблонам, регулярным выражениям, справочникам).
    - Автоматическое обновление каталога данных и тегов.

- **DLP**
    - Контроль:
        - отправки файлов с ПДн по почте наружу;
        - копирования данных на USB/внешние ресурсы;
        - массовых выгрузок из бизнес‑систем.

- **Configuration Compliance**
    - Автоматические проверки:
        - включено ли шифрование дисков на нужных серверах;
        - используются ли везде TLS;
        - нет ли слабых шифров и протоколов (отчёты по конфигурации).

### 4.2 Логирование и алертинг

- Централизованный сбор логов:
    - доступов к БД и файловым хранилищам;
    - действий пользователей в порталах и CRM/EMR/биллинге;
    - операций ETL/выгрузок в озеро данных.
- Алерты:
    - массовые чтения/выгрузки записей;
    - доступ к PHI/FIN из необычных зон/аккаунтов;
    - попытки доступа в обход ролей или из неавторизованных сервисов.

## 5. Реестр программных и аппаратных средств защиты

| Средство                        | Тип                         | Область применения                                | Что обеспечивает                                   |
|---------------------------------|-----------------------------|---------------------------------------------------|----------------------------------------------------|
| FDE (BitLocker / LUKS и аналоги) | Аппаратно‑ПО (шифрование дисков) | Серверы БД, файловые сервера, бэкап‑хранилища | Шифрование данных at rest                          |
| Шифрование на уровне БД         | ПО/функции СУБД             | БД порталов, EMR, CRM, биллинга                  | Защита PII/PHI/FIN на уровне таблиц/колонок        |
| TLS 1.2+ (HTTPS/mTLS)           | Протокол                    | Все веб‑порталы и API                             | Шифрование данных in transit                       |
| VPN / IPsec                     | Протокол/шлюзы              | Интеграции с внешними системами, филиалы         | Защита каналов передачи PHI/FIN наружу             |
| Хранилище секретов (Vault и др.)| ПО                          | Ключи шифрования, пароли БД, токены               | Централизованное и безопасное управление ключами   |
| Data Discovery / Classification | ПО                          | БД, файловые хранилища                            | Поиск и классификация PII/PHI/FIN, обновление реестра |
| DLP‑система                     | ПО                          | Почта, файловые ресурсы, рабочие станции         | Предотвращение утечек, контроль передачи данных    |
| SIEM / лог‑платформа           | ПО                          | Все сервисы, БД, инфраструктурные компоненты     | Корреляция событий, алертинг по инцидентам         |
| ETL + Masking/Anonymization     | ПО/скрипты                  | Путь в озеро данных, тестовые среды              | Маскирование и обезличивание для аналитики и тестов |
